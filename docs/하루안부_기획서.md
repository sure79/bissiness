# 하루안부 — 화장실 문이 전하는 부모님 안부

작성일: 2026-11-02
목표: iOS / Android 동시 출시. 1인 개발. 앱은 2~3주 내 심사 제출, 문 센서는 2단계로 판매.

---

## 1. 한 줄 정의

혼자 사시는 부모님 집 **화장실 문에 작은 센서**를 붙이면, 문이 여닫힐 때마다 자녀 폰에 "오늘도 괜찮으심" 신호가 쌓인다.
정해진 시간 동안 문이 한 번도 안 열리면 부모님 폰 → 자녀 폰 → 2차 보호자 순서로 알림이 간다.
부모님은 **아무것도 누르지 않아도 된다.** 센서가 없는 집은 폰 신호와 버튼으로 시작할 수 있다.

### 왜 화장실 문인가
- 사람은 하루 평균 4~7회 화장실에 간다. 건강한 성인이 12시간 넘게 안 가는 경우는 거의 없다.
- 현관문(외출 여부만 앎), 냉장고(안 열 수도 있음), 스마트플러그(TV 안 켤 수도 있음)보다 **생존과 직결된 행동**이다.
- 카메라·마이크가 아니라서 부모님이 감시받는 느낌이 적다. 문 개폐 횟수와 시각만 수집한다.
- 지자체 응급안전안심서비스도 문 센서를 쓰지만 대상자(기초수급·독거 등록)가 제한적이다. 민간에서 자녀가 직접 사서 붙이는 제품은 거의 없다.

## 2. 사용자와 역할

| 역할 | 누구 | 앱에서 하는 일 |
|---|---|---|
| 보호자(자녀) | 설치 결정권자, 결제자 | 가족 만들기, 센서 등록, 상태 확인, 알림 받기 |
| 어르신(부모) | 신호 발생자 | 거의 없음. 알림 뜨면 "괜찮아요" 한 번 누르기 |
| 2차 보호자 | 다른 자녀, 이웃, 친척 | 1차 보호자가 못 받을 때 알림 받기 |

어르신 폰이 없어도 작동해야 한다(센서 단독 Wi-Fi 전송). 폰이 있으면 신호원이 하나 더 늘어난다.

## 3. 신호 설계 (핵심)

### 3-1. 생존 신호원 (하나라도 있으면 "정상")
| 신호 | 출처 | 비고 |
|---|---|---|
| 화장실 문 개폐 | 문 센서 (2단계) | 가장 신뢰도 높음 |
| "괜찮아요" 버튼 | 어르신 앱 | 능동 신호 |
| 앱 실행 / 알림 탭 | 어르신 앱 | 수동 신호 |
| 걸음수 변화 | 어르신 폰 (iOS CoreMotion, Android Sensors) | 폰을 들고 다닐 때만 |
| 화면 켜짐 | Android만 (iOS는 불가) | 백그라운드 서비스 필요 |

MVP(1단계)는 위 표에서 센서를 뺀 4개로 출시한다. 센서 연동은 같은 앱의 2단계 업데이트.

### 3-2. 무활동 판정 규칙
```
감시 창: 06:00 ~ 23:00 (가족이 조정 가능, 취침 시간은 제외)
무활동 한계: 마지막 신호로부터 8시간 (기본값, 4~14시간 조정)

[0분]  한계 도달 → 어르신 폰에 "괜찮으세요?" 알림 (큰 글씨, 소리)
[+20분] 무응답 → 1차 보호자 푸시 "어머니 오늘 8시간째 신호가 없어요"
[+40분] 보호자 '확인함' 없음 → 2차 보호자 푸시 + (유료) 문자 발송
[+60분] 누구도 확인 안 함 → 모든 보호자에게 반복 알림, 전화 바로걸기 버튼
```
보호자가 "확인했어요"를 누르면 그 날 알림 종료. 사유(통화함, 방문함, 외출 중)를 남긴다.

### 3-3. 오탐 방지 모드
- **외출/여행 모드**: 보호자 또는 어르신이 켬. 기간 동안 감시 중지.
- **입원 모드**: 같은 원리, 메모 가능.
- **센서 끊김 알림**: 센서가 24시간 이상 서버와 통신이 없으면 "배터리/와이파이 확인" 알림을 따로 보낸다. 생존 경보와 섞지 않는다.
- **이상 빈도**: 문이 1시간에 10회 이상 여닫히면(복통, 낙상 뒤 반복 시도 가능성) "평소와 다른 패턴" 정보 알림을 보낸다. 경보가 아니라 정보로 표시.

### 3-4. 수집하지 않는 것 (심사와 신뢰를 위해 명시)
- 위치 정보. 쓰지 않는다. 쓰는 순간 **위치정보법상 사업자 신고** 대상이 된다.
- 카메라, 마이크, 통화 내역, 문자 내용.
- 건강 진단 결과. 걸음수는 "변화가 있었는지" 참/거짓만 저장하고 수치는 서버에 안 올린다.

## 4. 화면 구성 (MVP)

1. **온보딩**: 역할 선택(보호자 / 어르신). 어르신 모드는 글씨 1.5배, 화면 3개뿐.
2. **가족 연결**: 보호자가 6자리 코드 생성 → 어르신 폰에 입력. 또는 보호자가 어르신 폰을 직접 들고 설정.
3. **어르신 홈**: 큰 버튼 하나 "오늘도 괜찮아요". 오늘 보낸 신호 시간. 긴급 전화 버튼(보호자 번호).
4. **보호자 홈**: 어르신별 카드. 신호등(초록/노랑/빨강), 마지막 신호 시각, 오늘 신호 횟수, 외출 모드 토글.
5. **기록 달력**: 날짜별 첫 신호·마지막 신호·횟수. 월간 "평균 기상 시각" 요약.
6. **알림 설정**: 감시 창, 한계 시간, 2차 보호자 추가, 문자 백업 켜기(유료).
7. **센서 추가** (2단계): 센서 Wi-Fi 등록, 설치 위치 사진 안내, 테스트 개폐.

## 5. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 | Flutter | 한 코드로 양쪽 출시. 어르신용 큰 UI 만들기 쉬움 |
| 백엔드 | Firebase (Auth, Firestore, Cloud Functions, FCM) | 서버 운영 없음. 무료 구간 넓음 |
| 무활동 판정 | Cloud Scheduler 5분 주기 Function | 클라이언트에 의존하지 않음 |
| 로그인 | 전화번호 인증 + Apple 로그인 | 카카오 로그인을 넣으면 Apple 로그인도 **필수**(애플 규정) |
| 결제 | RevenueCat | 양쪽 인앱결제 통합, 영수증 검증 대행 |
| 문자 백업 | 네이버 클라우드 SENS 또는 알리고 | 건당 10~20원 |
| 센서 (2단계) | ESP32-C3 + 리드스위치 + 자석, 2×AA | 딥슬립으로 수개월 사용. 문 열릴 때만 깨어나 Firebase에 HTTPS POST |

### 데이터 모델 (Firestore)
```
families/{familyId}
  name, createdBy, plan(free|premium), watchWindow{start,end}, limitHours
  members/{uid}: role(guardian|elder|secondary), name, phone, fcmToken
  elders/{elderId}: name, awayMode{until, note}, lastSignalAt, status
    signals/{autoId}: type(door|button|app|steps|screen), at, deviceId?
    alerts/{autoId}: stage(1~4), firedAt, ackedBy?, ackedAt?, reason?
  devices/{deviceId}: elderId, kind(door), lastSeenAt, battery, wifiRssi
```

### 센서 → 서버 프로토콜 (2단계)
```
POST https://<region>-<project>.cloudfunctions.net/doorEvent
{ "deviceId": "HA-000123", "secret": "<기기별 키>", "event": "open", "battery": 2.9, "ts": 1730500000 }
```
Function이 secret 검증 후 signals에 기록, elders.lastSignalAt 갱신.

## 7. 준비 체크리스트

### 7-1. 계정·법무 (앱 개발 전 시작)
- [ ] **사업자등록** (개인사업자, 업종: 응용소프트웨어 개발 및 공급). 인앱결제 수익이 생기면 필요. 홈택스에서 1일.
- [ ] **통신판매업 신고** (구독 판매 시). 구청 또는 정부24, 등록면허세 약 4만원.
- [ ] **개인정보처리방침 페이지** URL. 양쪽 스토어 필수. GitHub Pages로 올리면 됨. 수집 항목: 이름, 전화번호, 신호 시각, 기기 식별자. 보관 기간, 삭제 방법 명시.
- [ ] **서비스 이용약관**에 면책 조항: "본 서비스는 응급구조 서비스가 아니며 알림이 지연·누락될 수 있습니다. 긴급 시 119." 이 문구는 앱 온보딩에도 넣는다.
- [ ] 위치정보 미사용 확인 (사용하면 방통위 신고 대상이므로 MVP에서 제외).
- [ ] **상표 검색**: 키프리스(kipris.or.kr)에서 "하루안부" 검색. 비어 있으면 출원(특허청 수수료 약 6만원 + 대행 시 20만원 안팎). 출원은 선택이지만 앱 이름이 나중에 바뀌면 손해가 크다.

### 7-2. Apple
- [ ] App Store Connect 앱 등록, 번들 ID 생성 (예: kr.haruanbu.app)
- [ ] APNs 인증 키(.p8) 발급 → Firebase에 등록
- [ ] Sign in with Apple 기능 활성화
- [ ] **심사 노트**: 테스트 계정 2개(보호자/어르신)와 가족 연결 코드를 적는다. 심사관이 혼자 두 역할을 다 볼 수 있어야 한다. 센서가 필요한 기능은 "데모 모드" 버튼 또는 시연 영상 링크 제공.
- [ ] 개인정보 영양표(App Privacy): 연락처 정보, 식별자, 사용 데이터로 표기
- [ ] 스크린샷: 6.9인치, 6.5인치 각 3장 이상 (Flutter 시뮬레이터로 캡처)
- [ ] 심사 거절 흔한 사유 대비: 4.2 최소 기능(기능이 너무 적다는 지적) → 기록 달력과 설정을 MVP에 꼭 포함. 5.1.1 데이터 수집 사유 → 전화번호 요청 시 이유 문구 표시.
- [ ] (선택) Critical Alerts 권한 신청: 무음 모드에서도 울리는 알림. 애플에 별도 양식으로 신청, 안전 앱은 승인 사례 있음. 1차 출시 후 신청.

### 7-3. Google Play
- [ ] 앱 만들기, 패키지명 동일하게
- [ ] **비공개 테스트 요건**: 2023년 11월 이후 개인 계정은 테스터 12명이 14일 연속 옵트인 상태여야 정식 출시 신청 가능. **지금부터 테스터 명단(가족, 지인, 교육 수강생)을 12명 이상 확보**하는 것이 일정의 최대 변수.
- [ ] 데이터 안전 섹션 작성 (수집 항목, 암호화 전송, 삭제 요청 방법)
- [ ] 백그라운드 센서(걸음수) 사용 시 "Physical activity" 권한 사유 설명
- [ ] 포그라운드 서비스 사용 시 (화면 켜짐 감지) 정책상 유형 선언 필요 → MVP에서는 빼고 걸음수만 쓰는 것을 권장

### 7-4. Firebase
- [ ] 프로젝트 생성, 리전 asia-northeast3(서울)
- [ ] Blaze 요금제 전환 (Cloud Functions 스케줄러에 필요, 무료 구간 안에서 거의 0원)
- [ ] 전화번호 인증 활성화 (한국 번호 SMS 요금 발생, 월 소량은 무료)
- [ ] 보안 규칙: 가족 구성원만 자기 family 문서 읽기/쓰기

### 7-5. 문 센서 (2단계, 앱 출시 후 착수)
- [ ] 1차 시제품: ESP32-C3 개발보드 + 리드스위치 + 자석 + 건전지 홀더. 부품비 1만원 이내. 딥슬립 전류 10µA 수준 확인.
- [ ] Wi-Fi 등록 방식: 앱에서 BLE로 SSID/비밀번호 전달 (ESP-IDF 표준 provisioning). 어르신 집 Wi-Fi가 없으면 보호자 폰 핫스팟 불가하므로 **Wi-Fi 없는 집은 1단계 폰 모드만 안내**.
- [ ] 케이스: 3D 프린팅 또는 기성 소형 케이스. 3M 양면테이프 부착.
- [ ] **KC 전파인증(적합성평가)**: 판매하려면 필요. KC 인증 받은 ESP32 모듈을 쓰면 완제품은 "적합등록" 절차. 시험비 50~150만원, 2~4주. 소량 선판매(지인·테스터)로 반응 본 뒤 진행.
- [ ] 배터리 경고: 전압 2.6V 이하면 보호자에게 교체 알림.

### 7-6. 운영
- [ ] 문의 이메일, 카카오 채널 하나
- [ ] 장애 시 대응 원칙: 서버 장애 시 모든 보호자에게 "현재 감시가 중단됨" 공지 푸시

## 9. 출시 뒤 성장 가설

- 설치 계기는 "명절 뒤"와 "뉴스에서 고독사 보도 뒤". 추석·설 2주 전에 광고 집중.
