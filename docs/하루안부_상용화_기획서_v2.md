## 0. 결론 요약

1. **1단계는 도어센서 없이 휴대폰 신호로 출시한다.** 60대 이상 부모 세대는 대부분 갤럭시를 쓴다. 안드로이드에서는 앱이 꺼져 있어도 잠금 해제, 화면 켜짐, 걸음, 움직임, 충전기 연결을 모을 수 있다.
2. **아이폰은 잠금 해제와 터치를 앱이 알 수 없다.** 아이폰 부모님은 "하루 한 번 알림 응답 + 걸음 기록" 방식으로 지원한다. 보호자인 자녀 쪽 앱은 아이폰과 갤럭시 모두 제약이 없다.
3. **삼성 스마트싱스 '패밀리 케어'가 이미 같은 감지를 한다.** 갤럭시 사용, 걸음 수, 삼성 가전 사용으로 부모님 이상 징후를 가족에게 알린다. 그래서 감지만으로는 이길 수 없다. 하루안부는 **알림 이후 확인 완료까지 책임지는 대응 체계**, **가족이 없는 1인가구**, **기관용 관리 화면**에서 차별화한다.
4. **도어센서는 직접 만들지 않는다.** 휴대폰을 거의 안 쓰시는 어르신을 위한 보조 수단으로 남기고, 출시 후 시판 센서 연동부터 검토한다.
5. **목표 일정**: 2027년 설(2월 6일) 2주 전 정식 출시. 오늘부터 약 10주.

> **2026-11-04 추가**: 1인가구용 "나의 안부(가칭 이상무)"를 먼저 출시하고, 가족용 하루안부는 같은 엔진으로 2027년 4월에 내는 순서를 `나의안부_기획서.md`에서 제안했다.

**시사점**
- 보호 대상 부모님 폰은 거의 갤럭시다. 부모님 쪽 기능은 안드로이드를 먼저 완성한다.
- 고독사 최대 위험군은 70~80대 부모가 아니라 **50~60대 남성 1인가구**다. 이혼, 사별, 미혼으로 혼자 사는 중장년은 자녀가 지켜보는 구조가 아니다. 그래서 본인이 설치하는 **"나의 안부"** 모드가 사회적으로 더 큰 시장이다.

### 1-3. 포지셔닝
**"알림으로 끝나지 않는 안부."** 감지, 본인 확인, 가족과 이웃 순서 연락, 확인 완료 기록까지 한 흐름으로 책임진다. 갤럭시든 아이폰이든, 가족이 있든 없든 쓸 수 있다.

차별화 다섯 가지:
1. **담당자 지정**: 형제 모두 알림을 받아도 한 명이 "제가 확인할게요"를 누르면 담당이 정해진다. 서로 미루거나 동시에 전화하는 일을 막는다.
2. **앱이 없는 사람도 연락망에**: 이웃, 관리사무소, 친척에게 문자·알림톡으로 2차 연락.
3. **본인 확인 단계**: 가족에게 알리기 전에 부모님 폰에 먼저 "괜찮으세요?"를 묻는다. 오탐이 줄어든다.
4. **1인가구 본인 모드**: 자녀가 아니라 본인이 설치하고 친구·형제를 연락처로 둔다.
5. **오프라인 설치 지원**: 시니어 스마트폰 교육 현장에서 직접 설치해 드리는 채널 (운영자의 AI 교육 강의 활용).

## 2. 1단계 방향: 휴대폰 신호 vs 도어센서

| 기준 | 휴대폰 신호 (추천) | 도어센서 직접 제작 |
|---|---|---|
| 출시까지 | 약 10주 | 시제품, 펌웨어, KC 적합성평가 포함 6개월 이상 |
| 초기 비용 | 개발자 계정, 서버 소액 | 부품, 케이스, 시험비 수십~백수십만원, 재고 |
| 설치 | 부모님 폰에 앱 설치 10분 | 방문 설치, 부모님 댁 와이파이 필요 |
| 신호 품질 | 폰을 자주 쓰시면 좋음. 폰을 두고 외출하거나 방전되면 약함 | 화장실 사용과 직결. 폰과 무관 |
| 확산 | 링크 공유로 무료 체험 | 기기 배송 필요 |
| 경쟁 | 삼성 패밀리 케어와 겹침 | 삼성 스마트싱스 센서·가전과 겹침 |

**결정**: 휴대폰 신호로 시작한다. 도어센서는 하드웨어 부담에 비해 경쟁 우위가 크지 않다. 다만 "폰을 거의 안 쓰시는 85세 이상" 같은 사용자가 파일럿에서 확인되면, 직접 제작 대신 KC 인증을 받은 시판 와이파이 도어센서나 스마트플러그 연동부터 검토한다.

## 3. 휴대폰 신호 감지 상세

### 3-1. 기본 원리
- 앱이 센서 원본을 계속 보내지 않는다. 운영체제가 이미 기록하는 사건(잠금 해제, 걸음 등)을 **15분 단위로 묶어 "활동 있었음" 요약**만 보낸다.
- 판정은 서버가 한다. 폰에서 경보를 결정하지 않는다. 그래야 폰이 꺼지거나 앱이 멈춘 경우도 잡아낼 수 있다.
- 자이로·가속도 원본을 백그라운드에서 계속 측정하지 않는다. 두 운영체제 모두 백그라운드 연속 측정을 제한하고 배터리 소모가 크다. 대신 **운영체제의 활동 인식 결과**를 쓴다. 운영체제가 같은 센서를 저전력 보조 칩으로 처리한 결과라서 사실상 같은 정보다.

### 3-2. 안드로이드 (부모님 대부분)
| 신호 | 알 수 있는 것 | 사용하는 기능 | 권한 | 강도 |
|---|---|---|---|---|
| 잠금 해제 | 사람이 폰을 열었다 | UsageStatsManager 이벤트 `KEYGUARD_HIDDEN` (안드로이드 9 이상) | 사용 정보 접근 (설정에서 직접 허용) | 강 |
| 화면 켜짐 | 화면이 사용 상태가 됐다 | 같은 기능의 `SCREEN_INTERACTIVE` | 같음 | 약 (알림으로도 켜질 수 있음) |
| 걸음 수 | 폰을 들고 움직였다 | Google Play 서비스 Recording API. 기기 안에 걸음 기록, 앱이 꺼져 있어도 기록, 10일 보관 | 신체 활동 | 강 (15분에 20보 이상) |
| 움직임 전환 | 가만히 있다가 걷기 시작 등 | Activity Recognition 전환 API | 신체 활동 | 중 |
| 충전기 연결·분리 | 사람이 충전기를 꽂거나 뺐다 | 배터리 상태 조회 | 없음 | 강 |
| 알림·위젯·앱 응답 | 직접 응답했다 | 앱 내부 | 알림 | 가장 강 |
| 하트비트 | 폰이 켜져 있고 앱이 살아 있다 | WorkManager 15분 주기 작업 | 없음 | 판정 보조 |

**하지 않는 것**
- 터치 좌표나 다른 앱 사용 내역 수집. 접근성 API로 화면을 읽는 방식은 구글 플레이 정책상 이 용도로 쓸 수 없다.
- 위치 수집. 위치를 쓰면 위치정보법 신고 대상이 된다.

**안드로이드에서 반드시 처리할 함정 네 가지**
1. **장기 미사용 앱 최대 절전 (안드로이드 11 이상)**: 몇 달 동안 앱과 상호작용이 없으면 백그라운드 작업과 FCM 푸시가 멈추고 권한이 초기화된다. 알림이나 위젯과의 상호작용은 사용으로 인정된다. 그래서 매일 아침 인사 알림에 응답하게 하고, 설치 때 "사용하지 않는 앱 일시중지"를 끄도록 안내한다.
2. **삼성 절전**: 일정 기간(삼성 문서 기준 현재 16일) 쓰지 않은 앱은 '딥 슬립'에 들어가 앱을 열 때만 동작한다. 설치 때 **절전 예외 앱**에 등록하도록 안내한다.
3. **대기 모드(Doze)**: 폰을 오래 그대로 두면 주기 작업이 미뤄진다. 정작 쓰러지신 상황이 이 경우다. 그래서 서버가 판정 직전에 **고우선순위 푸시로 폰을 깨워** 최신 기록을 가져온다.
4. **전체 화면 알림 제한 (안드로이드 14)**: 알람·전화 앱만 허용된다. "괜찮으세요?"는 소리가 나는 상단 알림으로 띄운다.

### 3-3. 아이폰
| 신호 | 가능 여부 | 방법 |
|---|---|---|
| 잠금 해제·터치 | **불가** | iOS는 잠금 해제나 다른 앱 사용을 앱에 알려주지 않는다 |
| 걸음·움직임 | 가능, 늦게 도착 | CMPedometer, CMMotionActivity. 폰이 최근 7일 기록을 보관하므로 앱이 깨어날 때마다 빈 구간을 채운다 |
| 앱이 깨어나는 기회 | 불확실 | 무음 푸시는 시스템이 횟수를 제한하고, 사용자가 앱을 강제 종료하면 오지 않는다. 백그라운드 새로고침은 시스템 재량 |
| 아침 인사 알림 | **확실** | 예약한 로컬 알림은 앱이 꺼져 있어도 울린다. 알림의 "괜찮아요" 버튼은 앱을 열지 않고 신호를 보낸다 |
| 홈 화면 위젯 버튼 | 가능 (iOS 17 이상) | 위젯 버튼이 바로 신호를 보낸다 |
| 단축어 자동화 | 검증 필요 | "충전기 연결 시", "알람을 끌 때" 자동화로 신호 전송. iOS 17부터 확인 없이 실행되지만 실행할 때마다 알림 배너가 뜬다 |

- 아이폰 부모님은 **"하루 한 번 응답 + 걸음 기록" 모드**로 안내한다. 기준도 다르게 둔다. 예: 아침 인사 미응답이고 오후까지 걸음 기록도 없으면 경보.
- 설치 때 "앱을 위로 밀어 끄지 마세요"와 "사용하지 않는 앱 정리하기 끄기"를 안내한다.
- 위치나 오디오 백그라운드 모드로 앱을 억지로 살려두는 방식은 앱스토어 심사 지침 2.5.4 위반이라 쓰지 않는다.

### 3-4. 전송 형식
15분마다 폰이 서버로 보내는 요약 예시:
```json
{
  "elderId": "e_123",
  "bucket": "2026-11-03T09:00:00+09:00",
  "unlock": 2,
  "screenOn": 3,
  "steps": 140,
  "motion": ["STILL>WALKING"],
  "charging": { "changed": true, "now": false },
  "interaction": ["morning_ok"],
  "battery": 64,
  "net": "wifi",
  "appVersion": "1.0.3"
}
```
- **보내지 않는 것**: 앱 이름, 위치, 통화·문자, 화면 내용, 센서 원본.
- **보관**: 15분 요약 30일, 하루 요약 1년. 탈퇴하면 즉시 파기.

### 3-5. 판정 로직
- **학습 기간 14일**: 평소 첫 신호 시각과 하루 최장 무신호 간격을 측정해 개인 기준을 제안한다. 예: 평소 최장 공백이 5시간이면 기준 7시간. 학습 중에는 정보 알림만 보낸다.
- **상태 네 가지**
  | 상태 | 조건 | 보호자에게 |
  |---|---|---|
  | 정상 | 기준 시간 안에 강한 신호 있음 | 초록불 |
  | 늦은 아침 | 평소 첫 신호보다 2시간 이상 늦음 | 정보 알림 (경보 아님) |
  | 무활동 경보 | 폰은 연결돼 응답하는데 기준 시간 동안 강한 신호 없음 | 대응 단계 시작 |
  | 연결 끊김 | 하트비트와 깨우기 푸시 응답이 모두 없음 | "폰 꺼짐·방전·인터넷 끊김 추정"과 마지막 배터리 잔량. 안부 판단 불가 상태로 표시 |
- **가장 의미 있는 경보는 "폰은 켜져 있고 응답하는데 아무도 만지지 않았다"이다.** 방전·꺼짐과 이것을 구분하는 것이 오탐을 줄이는 핵심이다.
- 취침 시간 제외, 외출 모드, 입원 모드는 v1과 같다.

### 3-6. 오탐 줄이기
- **아침 인사 알림**: 평소 기상 시각에 "좋은 아침이에요 [괜찮아요]". 하루 한 번 확실한 신호가 생기고, 안드로이드 최대 절전도 막는다.
- **폰을 두고 외출**: 1차 보호자 알림 문구를 "폰을 두고 외출하셨을 수도 있어요"로 시작하고 집전화·이웃 연락을 권한다.
- **자동 조정**: 경보 뒤 "괜찮았음" 결과가 반복되면 그 가구의 기준 시간을 늘리자고 제안한다.

### 3-7. 설치 마법사 (자녀가 부모님 폰에서 10분)
**안드로이드**
1. 부모님 본인 동의 화면 (수집 항목과 보관 기간)
2. 알림 허용
3. 신체 활동 허용
4. 사용 정보 접근 허용 (설정 화면으로 이동 후 복귀)
5. 배터리 절전 예외 앱 등록 (삼성: 배터리 > 백그라운드 사용 제한 > 절전 예외 앱)
6. "사용하지 않는 앱 일시중지" 끄기
7. 테스트: 화면을 끄고 잠시 뒤 잠금 해제 → 보호자 폰에 신호 도착 확인

**아이폰**
1. 부모님 본인 동의
2. 알림 허용
3. 동작 및 피트니스 허용
4. 홈 화면에 하루안부 위젯 추가
5. (선택) 단축어 자동화 "충전기 연결 시 신호 보내기"
6. 강제 종료 금지 안내, 사용하지 않는 앱 정리하기 끄기

각 단계는 앱이 실제로 권한이 켜졌는지 확인하고 초록 체크로 표시한다. 빠진 단계가 있으면 보호자 홈에 "설치 미완료"로 계속 보인다.

## 4. 대응 체계 (차별화 핵심)

```
[0분]   기준 초과 → 부모님 폰 "괜찮으세요?" 알림 (소리, 큰 버튼)
[+20분] 무응답 → 1차 보호자 전원에게 앱 알림. "제가 확인할게요" 버튼으로 담당자 지정
[+40분] 담당자 없음 또는 미해결 → 2차 보호자 (앱이 없어도 문자·알림톡): 이웃, 관리사무소, 친척
[+60분] 미해결 → 모든 보호자 반복 알림, 전화 바로 걸기, 119 연결 버튼과 비상 정보 카드
(추후 유료) 제휴 인력 방문 확인
```
- **결과 기록**: 통화함, 방문함, 외출 중, 병원 이동 중. 가족 모두에게 공유된다.
- **앱이 없는 연락처**: 문자는 발신번호 사전등록이 필요하다. 알림톡은 카카오 비즈니스 채널과 템플릿 심사가 필요하다.
- **119는 앱이 직접 신고하지 않는다.** 오신고 위험과 법적 책임 때문이다. 보호자가 누르는 119 연결 버튼과 주소·비상 정보를 제공한다.

## 7. 개인정보·법·스토어 체크리스트

- [ ] **부모님 본인 동의**: 부모님 폰 화면에서 직접 받는다. 자녀 동의로 대신할 수 없다.
- [ ] **걸음·활동 정보 별도 동의**: 건강 관련 정보로 볼 여지가 있어 민감정보 기준으로 따로 동의받는 것이 안전하다.
- [ ] **처리위탁·국외 이전 고지**: Firebase(구글) 사용 사실을 개인정보처리방침에 명시한다.
- [ ] **위치정보 미수집 유지**: 타이머 안부에 위치 공유를 넣으려면 위치기반서비스사업 신고를 먼저 한다.
- [ ] **의료기기 표현 금지**: "진단", "낙상 감지", "질병 예측"이라고 쓰지 않는다. 생활 리듬, 안부 같은 웰니스 표현만 쓴다.
- [ ] **면책 고지**: "응급구조 서비스가 아닙니다. 긴급 상황에는 119." 온보딩과 약관 모두.
- [ ] **사업 신고**: 사업자등록(기존 사업자는 업종 추가), 통신판매업 신고, 정기결제 해지 안내.
- [ ] **Google Play**: 건강 앱 신고서(모든 앱 필수), 데이터 보안 섹션, 사용 정보 접근·신체 활동 권한 요청 전 사전 고지 화면, 비공개 테스트 12명 14일.
- [ ] **App Store**: 개인정보 라벨, 동작 및 피트니스 사용 목적 문구, 백그라운드 모드 남용 금지, 심사용 데모 모드와 테스트 계정.
